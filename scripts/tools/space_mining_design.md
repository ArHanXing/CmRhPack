# 太空探索与采矿系统详细设计（CmRhPack）

> 状态：**架构方案 v2，待批准后进入实现**。本文替换早期“3 个轨道区 + 静态配方”的草案；没有修改游戏配方、任务、模组或配置。
>
> 核心决定：空间进度采用 **内太阳系 → 外太阳系 → 深空**；T2 卫星开启内太阳系并可获得粗超能硅岩，T3 卫星开启外太阳系和深空的终局矿产。每个目标天体按“测绘 → 登陆 → 永久据点”逐步开放。长程运输卫星在登陆后提供昂贵的小批量应急采矿；据点建成后提供低成本、可扩建的常规产量。

---

## 1. 目标与边界

太空系统承担四类价值：

1. **开辟地面没有的来源**：优先补上 `jsonreg:raw_naquadria` 等指定缺口；T2 卫星必须能参与超能硅岩线。
2. **支撑后期规模**：为 Avaritia 奇点和终局配方提供可扩充的原料吞吐，但不要直接跳过地面复杂加工链。
3. **奖励探索投资**：同一目标从首次发现到建立据点，有清晰的阶段、专属物品与视觉反馈。
4. **允许继续扩展**：新增天体主要通过数据定义和配方/产出表扩展，不反复重写状态机。

太空矿物原则上产出**粗矿、矿簇或浓缩物**，仍须接入地面磨矿、化学处理、冶炼。未明确批准前，不直接给成品锭、成品粉或燃料棒。尤其 `raw_naquadria` 是 T2 的重要供料，不应把超能硅岩后续富集、去共振、浸出和精炼环节一并跳过。

## 2. 进度分区与卫星等级

这里的“卫星等级”表示有效任务载荷和航程，不是太空区域本身。解锁某区域仍需完成对应任务。

| 等级 | 可达范围 | 系统定位 | 建议燃料 | 主要用途 |
|---|---|---|---|---|
| T1 近地试验载荷 | 近地轨道 | 学会制造、灌注、回收与遥测；不开放大宗稀有采矿 | RP-1/液氧；甲烷/液氧可作为替代 | 教学、遥测、低产校准样品 |
| **T2 行星际卫星** | **内太阳系** | 中后期工业扩张；能采到粗超能硅岩 | MMH/N₂O₄ 或 UDMH/N₂O₄；具体由成本平衡决定 | **小行星带粗超能硅岩**、内行星常见稀有料 |
| **T3 深空卫星** | **外太阳系 + 深空** | 终局金属、极稀有料与远距离勘探 | 液氢/液氧 | 铂、铀、铱相关粗料/浓缩物；深空独占物 |

### 为什么 T2 即可开超能硅岩

粗超能硅岩是 T2 后段的工业目标与后续高温/核能链的入口，不应被锁到已经需要终局材料才能造的 T3。它从内太阳系小行星带进入产线，保持“**找到来源不等于得到成品**”：小批量原矿可以应付首次样品和启动，规模化处理依靠已建成的太空据点。

T3 的价值改为**另一组终局金属和深空特有资源**，不是把 T2 的同一批矿物简单乘数量。外太阳系可先选择现有注册表支持的原料，例如 `oritech:raw_platinum`、`oritech:raw_uranium`；深空可评估 `jsonreg:iridium_concentrate` / 铱碎块等现有中间品。最终名单须以注册物品、地面配方和资源缺口核对为准，不新造无下游价值的矿。

### 初期可用的天体目录（内容草案）

| 分区 | 目标 | 定位 / 首选资源 | 卫星门槛 |
|---|---|---|---|
| 内太阳系 | 近地轨道 | 教程任务和通信基站，不做无限矿源 | T1 |
| 内太阳系 | 小行星带（主矿区） | `jsonreg:raw_naquadria`；低概率伴生普通金属样品 | T2 |
| 内太阳系 | 水星轨道 | 高温、耐热材料/少量铂族样本；具体矿表待平衡 | T2 + 水星测绘 |
| 外太阳系 | 木星系统 | `oritech:raw_uranium` 等放射性/高密度矿料 | T3 + 木星登陆 |
| 外太阳系 | 土星环 | `oritech:raw_platinum` 等稀有金属矿料 | T3 + 土星登陆 |
| 深空 | 游荡小行星 / 彗星云 | 铱浓缩物、稀有催化材料等低频终局料 | T3 + 深空阵列 + 深空测绘 |

表中矿物只是设计归属，不能在实现前视为已定。首个垂直切片建议只做**小行星带 + 木星系统 + 一处深空目标**，其余天体保留扩展位。

## 3. 天体探索状态机

每个天体独立保存状态：

```text
UNSURVEYED ──测绘任务完成──► SURVEYED
SURVEYED   ──登陆任务完成──► LANDED
LANDED     ──据点建设完成──► OUTPOST_ACTIVE
OUTPOST_ACTIVE ──可暂停/重建──► OUTPOST_SUSPENDED (可选，首版可不做)
```

状态**单向升级**。任务失败、玩家离线、服务器重启或机器损坏不清除已完成阶段；不做永久失去卫星或进度倒退。想增加风险感，用额外耗材、延迟、任务中断成本表达，不用随机销毁昂贵关键物。

### 阶段 A：测绘（Survey）

**目的**：确认天体存在、轨道窗口和资源分布，解锁后续登陆任务及“远程采样”。

- 在任务控制台选择目标，准备一枚该目标的测绘探针、对应等级的卫星载荷、推进剂和遥测/计算组件。
- 发送后建立持久任务记录，进入 `IN_FLIGHT`，显示目标、消耗、预计返回时间和阶段。
- 到达时间后结算，生成该天体专属的测绘数据/图谱，并将天体状态置为 `SURVEYED`。
- 首次测绘可由 FTB Quests 展示“交付数据/建立下阶段任务”，但真正的门禁由模组世界状态判断；不能只靠玩家是否点过任务。
- 测绘结果可显示矿物类别、危险等级、推荐卫星级别与预计产出，不必暴露全部数值。

**建议投入**：中等一次性成本；时间短于登陆。主要消耗探针、推进剂和少量高阶电路，回报是新路线和可执行的远程采样。

### 阶段 B：登陆（Landing）

**目的**：在已测绘天体建立短期作业窗口，解锁昂贵、低产的“长程航运卫星采矿”。

- 需要 `SURVEYED`、对应等级卫星、登陆/捕获舱、着陆腿或机器人作业组件、生命保障/热防护等目标条件。
- 任务结算后状态进入 `LANDED`，获得一枚“登陆许可/地表锚点”作为纪念与任务展示；真正的授权也记录在服务器状态。
- 登陆后可做**长程运输卫星**任务：发射专用单程采矿包，载荷回收能力弱、单位成本高，但不需要先建永久据点。
- 长程采矿每次只给小批量稀有资源，适合首次样品、补一两次配方缺口、启动后续生产线；不应成为奇点量产的最佳方案。

**成本定位**：单件资源成本显著高于据点（目标为约 5–10 倍，作为平衡指标而非固定公式）。任务输出数量控制在“能继续推进流程，但不能长期替代产线”的档位。

### 阶段 C：永久据点（Permanent Outpost）

**目的**：付出高额资本投资，把一次性采样转换成可自动化、可扩产的资源供应。

- 需要 `LANDED`，并交付据点核心、能源/热控、通信中继、自动化钻机、运输仓和数批结构材料。
- 建设任务是**高额一次性成本**，完成后将 `OUTPOST_ACTIVE` 写入世界数据。据点核心/卫星不作为普通采矿配方的消耗品。
- 建成后该天体开放常规“据点采矿”：卫星/授权常驻，采掘模块反复产出，主要成本改为电力、可选低价维护耗材或运输周期。
- 据点产出应比长程采样**成本/件低很多**，并拥有稳定、可并行的吞吐；高阶金属仍保持合理速度，避免一座据点瞬间取代所有地面产线。
- 可扩建等级：基础据点 → 自动化采掘阵列 → 深空物流枢纽。扩建提高批量/并发槽位，而不是给无上限倍增。

**回本原则**：设据点投资成本为 `C_outpost`，长程单批净成本为 `C_remote`，每批收益原料量为 `Q_remote`，据点每周期净成本/产量为 `C_outpost_cycle` / `Q_outpost_cycle`。至少满足建立据点后长期单位成本明显低于长程采样，且在合理批次数内回本。具体回本批数应按实际火箭燃料线与终局需求模拟，推荐先用 8–15 批作为测试目标，不把它当作未经验证的最终值。

## 4. 卫星与运输的玩法区分

不要把“卫星”同时当一次性燃料、许可、矿工和行星状态。建议拆成四类对象：

1. **卫星平台（可重复使用）**：T1/T2/T3 的任务航程和载荷能力。装到电梯采掘模块或任务控制台上；不在每轮采矿时消耗。
2. **任务探针（单次消耗）**：只用于首次测绘，回收数据，不产大量矿。
3. **长程采矿运输包（单次消耗）**：登陆后的高成本小批量采矿；可用现有灌注无人机与燃料来表达一次远征。
4. **据点核心（一次性建设投入）**：落地后长期解锁某个天体的低成本开采。

### 卫星能力配置

| 配置 | 功能 | 建议规则 |
|---|---|---|
| T1 近地遥测卫星 | 首个教程任务、短程测绘 | 不能开采小行星带超能硅岩 |
| T2 行星际采矿卫星 | 内太阳系访问 | 可测绘/登陆小行星带，可采 `raw_naquadria`；需对应推进剂和任务许可 |
| T3 深空通信与采矿卫星 | 外太阳系、深空 | 可到木星/土星/深空；开采高阶金属依然要求各自测绘、登陆/据点阶段 |
| 长程运输载荷 | 登陆后的高价远程采矿 | 一次任务一批小产量；T2/T3 按目标需求制造不同版本 |
| 据点中继阵列 | 常规矿业通信、物流 | 建成后常驻，不每个配方消耗；支持多台采掘模块并行 |

**重要约束**：有 T3 卫星不等于所有 T3 星球自动开放。先解锁的是“能飞到”，各天体的测绘与登陆状态仍是独立门禁。

## 5. 采矿模式与配方/数据模型

### 模式 1：长程采样/航运

```text
已登陆目标 + 对应长程运输包 + 推进剂 + 目标专用载荷
    → 少量目标原矿 + 空/回收件（若相应任务有回收能力）
```

- 每次任务消耗专用载荷；卫星平台可返回，具体是否返还由任务定义决定。
- 高成本、短产量、可以在据点前使用。
- 输出是一个有限的材料批次，不要做成可无限循环的“卫星 + 燃料 → 卫星 + 任意矿”。

### 模式 2：永久据点采矿

```text
OUTPOST_ACTIVE 授权 + 常驻卫星平台 + 采掘模块 + 电力/低价维护
    → 稳定产出该天体原矿
```

- 每个采掘模块在 GUI 中绑定一个目标天体；同一模块不可同时跨目标产矿。
- 服务器检查：该世界/队伍是否已建据点、模块卫星等级是否足够、配方天体是否与模块绑定目标相同。
- 将模块目标、卫星平台、任务状态写入存档；搬机器或重启服务器后仍然有效。
- 目标切换需要返航/重新部署动作，而不是瞬间改下拉框，避免同时占有所有行星收益。

### 数据驱动配方定义

建议每种目标资源定义数据包 JSON，而非把逻辑散落在多条 CraftTweaker 配方中：

```json
{
  "body": "asteroid_belt",
  "zone": "inner_solar_system",
  "requiredSatellite": "t2",
  "requiredState": "outpost_active",
  "recipeMode": "outpost_mining",
  "durationTicks": 2400,
  "energyPerTick": 2048,
  "inputs": ["power", "maintenance_item_optional"],
  "outputs": [{"item": "jsonreg:raw_naquadria", "count": 8}],
  "byproducts": []
}
```

以上数值仅说明字段含义，不是已平衡的配方。长程任务用另一种 recipe mode 并受任务控制器调度，不应仅靠普通配方无限循环。

## 6. Java 实现架构（推荐）

仓库当前是整合包实例与脚本/配置目录，尚未发现可直接编译的 Java 模组工程。因此需要新增一个 Fabric 1.21.1 配套小模组（暂名 `cmrh-space`），或后续把同等功能并入现有自制模组。无需改 Oritech/TR 源码；尽量通过新增内容与兼容钩子实现。

### 核心模块

1. **天体注册表**：读取 `data/cmrhspace/celestial_bodies/*.json`，含 ID、所属分区、卫星等级、阶段成本、飞行时间、资源表、提示文本。校验资源 ID 存在、阶段引用有效、配方无空输出。
2. **世界任务状态 `SpaceProgressState`**：基于 MC 1.21.1 的 `PersistentState` 保存每个世界/队伍的天体阶段、进行中任务、完成记录、据点等级、已绑定模块。服务端权威，客户端只读同步。
3. **任务控制终端**：方块/方块实体 GUI 列出已知天体、阶段目标、材料/能量需求、ETA、任务日志；玩家从此派遣、回收数据、申请登陆和建设据点。
4. **任务调度器**：任务启动时服务端原子扣除物料并记录 `startTick/completeTick`；世界时间到期结算。支持服务器关闭再开、区块卸载、客户端断线；任务进度不可重复结算。
5. **卫星/模块绑定**：把卫星等级和目标天体写入采掘模块的 BlockEntity NBT；同一卫星不能被多个模块重复占用。GUI 显示“已部署/返航/闲置”。
6. **采矿授权检查**：在开始配方时验证当前世界进度、模块绑定、目标阶段与卫星能力；不满足时不给启动或继续进度。不能由客户端伪造许可。
7. **EMI/配方展示**：显示配方基础资源与所需行星状态；未解锁内容可显示为“需完成测绘/据点”，但不要把隐藏配方泄露成可直接合成。
8. **FTB Quests 集成（展示层）**：新增太空计划章节显示步骤、收集任务和叙事；核心状态由模组保存。可以加可选 FTB Quests API 监听或命令桥接，但不能因任务书未加载就卡死世界状态。

### 任务状态数据

```text
MissionRecord {
  missionId, teamOrWorldId, bodyId, stage,
  status: PREPARING | IN_FLIGHT | READY_TO_CLAIM | COMPLETED | ABORTED,
  launchedAt, completesAt, consumedInputs, returnPayload,
  assignedSatelliteId, assignedElevatorId
}

BodyProgress {
  bodyId,
  stage: UNSURVEYED | SURVEYED | LANDED | OUTPOST_ACTIVE,
  outpostLevel,
  surveyDataClaimed,
  activeSatelliteId,
  boundMiningModules[]
}
```

任务使用幂等结算 ID；同一任务最多发奖一次。若库存无法接收回报，状态停留在 `READY_TO_CLAIM`，不能销毁奖励。首版不设随机任务失败。

### 任务成本与时间

- 启动任务前先检查全部物料、能源和卫星状态；材料要么原子扣除，要么完全不扣。
- 任务时长按游戏 tick 计时，可通过配置调整；不要求维持区块加载。
- 暂定时间量级：测绘数分钟、登陆约 5–10 分钟、据点建设约 10–20 分钟；这些是体验目标，测试后再定。
- 大型任务可由任务终端并行槽位控制：初期 1 槽，T3 升级后 2–3 槽；不要简单用“多造终端无限并行”。
- 中断只提供“撤回并损失已投入的可消耗任务载荷”选项；主要进度不回退。避免随机摧毁高价值卫星。

## 7. 资源与经济平衡

### 资源分层

- **地面**：常见矿、基础加工、复杂化学分离与冶炼仍是主链。
- **T2 小行星带**：`jsonreg:raw_naquadria` 的稳定入口，输出粗料，不输出 `naquadria_dust`、锭或燃料棒。
- **T3 外太阳系**：可批量供应铂、铀等已存在原料，为终局配方提供规模；下游仍需要本地处理。
- **T3 深空**：铱浓缩物等稀有/专属原料，低频但明确用途；若某材料没有下游就暂不加入矿表。

### 长程与据点的目标差异

| 项目 | 长程航运采样 | 永久据点 |
|---|---|---|
| 可用阶段 | 登陆后 | 据点建成后 |
| 资本成本 | 每次都高 | 首次建设很高 |
| 单次产量 | 小批量 | 稳定批量 |
| 单位资源成本 | 高 | 明显低 |
| 是否适合自动化 | 不适合长期跑 | 适合多模块并行 |
| 设计用途 | 解锁/补缺/试产 | 主力规模化供料 |

### 反滥用与不会做的事

- 不让测绘数据作为可复制普通物品，单凭堆叠数据绕过阶段。物品可以展示/交任务，真实许可留在世界数据。
- 不给普通采矿配方无限返还燃料、无人机和单次运载舱；明确每批消耗。
- 据点矿产不直接产精炼品；不让 T2 超能硅岩绕过既有 `process_naquadah.zs` 流程。
- 不要求玩家在太空维度实际生存或常驻 chunk；异步任务是抽象任务，避免维度/传送/服务器负担。
- 不用随机失败永久损失卫星；体验成本由推进剂、任务时间、模块占用和昂贵建设构成。

## 8. FTB Quests 叙事与玩家流程

现有太空电梯章节已介绍太空组装、发射卫星，以及电梯装配机/采矿机。新系统应扩展该章节，而不是另开互不相连的入口。

建议章节节点：

1. **电梯竣工**：拥有电梯、动力模块、组装机、采矿模块。
2. **近地链路**：制造 T1 卫星并派出首次遥测任务，获得“地面站已联通”。
3. **T2 行星际许可**：制造并灌注 T2 卫星；完成火箭燃料/计算负载目标。
4. **小行星带测绘**：提交返回的测绘数据，开启登陆。
5. **首次远程采矿**：在登陆后完成一次高价、低产的粗超能硅岩采样。
6. **建立自动化据点**：提交据点核心、能源和钻机组件，开启低价常规采矿。
7. **T3 深空通信**：制作液氢推进的 T3 深空卫星，开放外太阳系任务。
8. **外太阳系矿业**：对木星/土星分别执行测绘、登陆、据点建设，解锁各自终局金属。
9. **深空阵列**：建设高额终局设施，解锁铱浓缩物/深空专属资源。

任务书奖励建议为名称文本、样品、蓝图/首发优惠和制造材料，不发大批量关键矿物；否则会削弱“长程昂贵、据点回本”的经济结构。

## 10. 验收标准

系统可称为完成，至少满足：

- [ ] 玩家能从现有 FTB 太空电梯章节自然进入任务控制终端。
- [ ] T2 卫星可在完成阶段后获得粗超能硅岩，且未跳过超能硅岩处理链。
- [ ] T3 卫星开放的是其他终局金属/稀有资源，而非仅高倍复制 T2 输出。
- [ ] 每个目标天体状态独立保存；没有登陆不能派长程采矿，没有据点不能跑低成本常规矿。
- [ ] 长程采样成本/件明显高于据点，且适合一次性补缺而非自动化主产线。
- [ ] 建设据点是明显资本开支；建成后支持可预测的低成本扩产和并行模块。
- [ ] 世界重启、区块卸载、多玩家和任务重复领取不会产生重复奖励、丢失卫星或回退进度。
- [ ] 资源表只使用已注册且有下游的原料；配方槽位、能耗、推进剂消耗经过实际审计。
- [ ] FTB Quests 负责叙事与展示，服务端任务状态负责真正授权，不会因任务书关闭而绕过/锁死进度。

## 11. 待批准的默认值

为避免设计无限发散，建议后续按以下默认方案推进：

1. 分区采用**内太阳系 → 外太阳系 → 深空**；近地轨道只作 T1 教程层，不算独立终局资源区。
2. T2 解锁小行星带并产粗超能硅岩；T3 解锁外太阳系与深空金属。
3. 每个天体固定走**测绘 → 登陆 → 据点**；登陆后有高价小批量长程采样，据点后有低成本常规采矿。
4. 阶段状态使用 Java 世界存档，卫星和采矿模块使用服务器端绑定；FTB Quests 只显示任务线。
5. 首期只做小行星带一个完整天体垂直切片，验证后再铺 T3 多天体；不先造太空维度或随机失败系统。
6. 首期不锁定配方精确数值；先按资源总需求、火箭燃料制造链、据点回本批数和并发吞吐模拟后再填表。
