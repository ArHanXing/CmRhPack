## 一、机器实测模型（地基）

### 1.1 结构与接口

| 项 | 实测值 |
|---|---|
| 配方类型 ID | `techreborn:naquadah_deresonator`（已注册进 `RECIPE_TYPE` + `RECIPE_SERIALIZER`，CraftTweaker 可直接 `addJsonRecipe`） |
| 多方块 | 3×3×5。上下两层各 9 个 `basic_machine_casing`，中间三层各 8 个 `industrial_machine_casing` 围成中空（共 18 + 24 = 42 个外壳） |
| 输入槽 | **2** 个（槽位 0、1） |
| 输出槽 | **4** 个（槽位 2、3、4、5） |
| 能量槽 | 1 个（槽位 6） |
| 内部储罐 | **100 B**（`FluidValue.BUCKET × 100`） |
| 能量缓冲 / 最大输入 | 1,000,000 E / 512 EU/t（`config/techreborn/machines.json`） |
| 配方 JSON | `{type, power, time, fluid, ingredients[], outputs[]}` |

### 1.2 运行循环（`tick` + `drainIntoRun`）

配方运行期间，**每 5 tick 把整个储罐清空一次**，清出的毫桶数累加进 `runFluidMb`：

```
t = 5, 10, 15, …（严格小于 currentNeededTicks）
每次：runFluidMb += 罐内 mB;  罐 = 空
窗口数 n = ⌊(time − 1) / 5⌋      // time=200 → 39；240 → 47；600 → 119；800 → 159
```

配方开始时（`currentTickTime == 0`）`runFluidMb` 归零；**罐里剩的液会顺延到下一次配方**。

### 1.3 成功率（`successRate(long)`，逐行核对）

```
p(F) = (0.1 + 0.1·⌊F/10000⌋) · 2^(−10·(F mod 10000)/F)      // F = 本次配方累计喂入的 mB
F = 0 → 0.1
```

| 累计流体 F | 成功率 | 备注 |
|---|---|---|
| 0 | 10% | 空罐硬跑 |
| 10 B | 20% | |
| 20 B | 30% | |
| 40 B | 50% | |
| 50 B | 60% | |
| 70 B | 80% | |
| **90 B** | **100%** | **精确命中即满概率** |
| 100 B | 110% → 100% | 恰好一整罐 |
| 94 B | 74.5% | 尾数 4 B 的代价 |
| 99 B | 53.3% | 尾数 9 B，掉一半 |
| **150 B 及以上** | **100%（免尾数）** | u ≥ 15 时乘数 1.6 足以压过最坏惩罚 0.648 |

两个反直觉的点，**这是整个设计的钥匙**：

1. **略高于 10 B 整数倍是安全的，略低于则是灾难。**
   10,100 mB → 1.0 × 2^(−0.0099) = 99.0%；9,900 mB → 0.1 × 2^(−0.99) = **5.1%**（差一点点，只剩 1/20）。
2. **喂多了反而免罚。** F ≥ 150 B 时浮点乘数足够大，尾数再差也 ≥ 100%。
   所以「暴力洪水」是可行的，只是贵。

### 1.4 成败代价（`RecipeCrafter.updateEntity`）

```
if (能放下产物) {
    if (rollCraftSuccess()) { 产出 } else { finishCraft() }   // 失败走同一个 finishCraft
}
finishCraft() → useAllInputs(); currentTickTime = 0;
```

**失败 = 吃掉全部输入 + 全部已喂流体 + 零产出，进度清零。**
这条把机器的定位钉死了：**放在输入越贵的地方，它越狠。**

### 1.5 维度

下界：时间 ×1.0、EU/t ×1.0。
非下界：时间 ×1.5、EU/t ×0.8 → 有效时间 `round(time × 1.5)`。

账：**非下界 = 同样流体、总电 ×1.2（1.5 × 0.8）、吞吐 ÷1.5。**
（注意没有"流体省 1.5 倍"这回事——F 是累计总量，与时长无关。）

### 1.6 ⚠️ 进液约束（tooltip 没写，但决定一切）

机器**没有流体槽**，GUI 里也不画流体槽（`createScreenHandler` 只挂了 0/1 输入、2–5 输出、6 能量）。它唯一的进液途径是 RebornCore 在 `onInitialize` 里注册的**全局 `FluidStorage.SIDED` 回退**——也就是**只能靠管道/相邻储罐从外面压进去**。

而整合包里能在管道里流动的液体，基本只有 **Oritech 机器产出的流体**（TR 机器的流体一律走单元，进不了管道）。所以：

> **阻尼液必须是 Oritech 流体链里的东西。** 这不是审美问题，是能不能跑起来的问题。

### 1.7 管道流速（设计杠杆的真实刻度）

| 管道 | 配置值 | 折算 |
|---|---|---|
| `oritech:fluid_pipe` | `fluidPipeExtractAmountBuckets = 2`，`…IntervalDuration = 10` | 2 B / 10 tick = **1 B / 5 tick 窗口** |
| 管道 + `oritech:pipe_booster_block` | 速率 ×100 | 200 B / 10 tick = **100 B / 窗口 = 恰好一整罐** |

**储罐容量 100 B = 10 个成功单位，正好等于增幅管一个窗口的输送量。** 这不是巧合，作者把量杯做进了罐子：

> 增幅管持续供液 → 每个窗口必定灌满 100 B → `F = 100 B × n` → `u = 10n` → **恒定 100%**，
> 代价是 `n × 100 B` 的流体（time=600 时是 11,900 B/次）。

## 二、三个设计杠杆

| 杠杆 | 我（设计者）能设 | 玩家能调 |
|---|---|---|
| **`time`** | 窗口数 n，从而决定"某流速 → 累计 F" | — |
| **批量大小** | 一次配方吃 N 个物品 → 每件流体成本 = F/N | — |
| **流体身份** | 阻尼液来自哪条链、多贵 | 流速 / 是否精确计量 |

经济学（记每 B 流体成本为 c，单件输入价值为 V）：

| 策略 | 成功概率 | 期望流体/件成功 | 期望输入损失 |
|---|---|---|---|
| 赌博 10 B | 20% | 50 B | 5 V |
| 保险 90 B | 100% | 90 B | V |
| 洪水 ≥150 B | 100% | ≥150 B | V |

**赌博 vs 保险的盈亏平衡：`V < 10c` 时应该赌，`V > 10c` 时应该买保险。**
→ 这条规则会自动教会玩家「便宜的粉随便赌，八道工序的粉必须保」。
**设计任务就是让两道闸门分别落在平衡点的两侧。**

## 三、线体重写

### 3.1 总体拓扑：单主干、两道质检口

```
末地矿石
  └─ 磨粉 → 粗硅岩 → 工业磨粉 → 粉碎硅岩 → 离心
                                              ├─ 硅岩粉 ──→（普通线）硅岩锭 / 硅岩板 / 催化烧
                                              └─ 含杂富集硅岩粉
                                                     │
                                        ╔════════════▼════════════╗
                                        ║  闸门①  解谐器（下界）  ║  阻尼液：硫酸
                                        ╚════════════┬════════════╝
                                                     │ 富集硅岩粉（唯一通路）
                                        ┌────────────┴────────────┐
                                        ▼                         ▼
                              硫酸溶出 → 五道湿法          粒子对撞（加速器）
                                        │                         │
                                  富集硅岩锭                   粗超能硅岩
                                                                  │
                                                          八道湿法（现有 nqdria.1–9a）
                                                                  │
                                                             超能硅岩粉
                                                                  │
                                                    ╔═════════════▼═════════════╗
                                                    ║  闸门②  解谐器（下界）    ║  阻尼液：氟化铵废液
                                                    ╚═════════════┬═════════════╝
                                                                  │ 热超能硅岩锭
                                                            真空冷冻 → 超能硅岩锭
                                                                  │
                                                            ★ T2 结束 / T3 开门
```

### 3.2 改动清单（逐条配方级）

#### A. 入口整备

| # | 操作 | 内容 | 理由 |
|---|---|---|---|
| A1 | **删除** `nqdh.0b.leach_enriched_naquadah_ore` | 富集矿石直溶成溶液 | 这是全条线最大的免费午餐：把「磨粉→工业磨粉→离心→酸溶」四道压成一道 |
| A2 | 新增 `nqdh.0b.grind_enriched` | 工业磨粉机（水）：`end_enriched_naquadah_ore ×1` → `crushed_naquadah_ore ×3`，time 300 / power 64 | 富集矿石仍是更好的入口（3 个粉碎料 vs 普通矿石绕一圈得 1 个），但不再跳工序 |

#### B. 闸门①：解谐（新）

```
nqdh.1b.deresonator
  机器：techreborn:naquadah_deresonator
  time 240 / power 256        → n = 47
  流体：oritech:still_sulfuric_acid
  输入：impure_enriched_naquadah_dust ×4
  输出：enriched_naquadah_dust ×4
```

- **改 `nqdh.3.refinery` 的输入**：`impure_enriched_naquadah_dust ×10` → `enriched_naquadah_dust ×10`。
  于是解谐器成为**唯一通路**。
- 它救活一个孤儿物品：`jsonreg:enriched_naquadah_dust` 目前只有 tooltip 和 `c:dusts` 标签，**没有任何产出者**。
- 定位：**教学闸门**。输入便宜（4 个含杂粉 ≈ 8 个粉碎料），硫酸也是大宗货 → 玩家敢赌。
  47 窗口下各种喂法的实测概率：

| 喂法 | 累计 F | 成功率 | 每件流体 |
|---|---|---|---|
| 1 根基础管 | 47 B | 17.8% | — |
| 2 根基础管 | 94 B | 74.5% | 23.5 B |
| **3 根基础管** | 141 B | **100%** | 35.3 B |
| **精确计量** | 90 B | **100%** | **22.5 B** |
| 赌博 | 10 B | 20% | 期望 50 B / 成功 |

#### C. 超能线的入口：给 `raw_naquadria` 一个来源

`raw_naquadria` 目前 **0 产出**（只有 tooltip），整条 nqdria 线是死的。这正是 TODO 里 T2.4 的「超能硅岩 + 粒子碰撞」：

```
nqdria.0.collision
  机器：oritech:particle_collision
  time 2400
  输入：enriched_naquadah_dust ×1 + oritech:overcharged_crystal ×1
  输出：raw_naquadria ×1
```

- 用 `enriched_naquadah_dust`（闸门①的产物）而不是 `naquadah_dust`，把富集线和超能线**串成单主干**：闸门① 从此是两条支线共同的咽喉。
- 过充水晶本身已经是粒子对撞产物（`t2.zs` 里 time 2000）→ **加速器成为 T2.4 的入口，解谐器成为 T2.4 的出口。**

#### D. 超能线整备

| # | 操作 | 内容 |
|---|---|---|
| D1 | 重命名 `wtf` → `nqdria.1.grinder`，删掉上方注释掉的死配方 | 那个配方名会污染配方表；且被注释的死配方和活配方参数不一致，容易误读 |
| D2 | 修正 `nqdria.7.blast_furnace` | 注释写「钙蒸气」但实际喂的是氩气。改成真的用钙（`jsonreg:calcium_oxide_slag` 的产线在 `t2.zs` 已有），让注释和配方一致 |

#### E. 闸门②：终末解谐（T2 收尾）

```
nqdria.final.deresonator        ← 取代 nqdria.final.ebf
  机器：techreborn:naquadah_deresonator
  time 600 / power 512          → n = 119
  流体：jsonreg:ammonium_fluoride_waste（氟化铵废液）
  输入：naquadria_dust ×1
  输出：hot_naquadria_ingot ×1
```

- 输入是**八道工序 + 一次粒子对撞**的产物 → V 极大 → 按 `V > 10c` 规则，玩家**必须买保险**。
- 阻尼液是**阶段五的废液**（`nqdria.5.refinery` 的 `fluidOutputs`，Oritech 精炼厂直出，可管道 ✓）。
  它目前只有一条出路：`nqdria.misc.nh4f_decomposition` 电解回收成 NH₃ + HF（2 B → 1 B + 1 B）。
  **解谐器要烧掉同一股废液 → 玩家必须在「回收氨和氢氟酸」和「买成功率」之间做取舍。**
  这是全案我最满意的一处：**收尾闸门逼你烧掉自己本想回收的东西。**
- 119 窗口下的实测概率：

| 喂法 | 累计 F | 成功率 | 每件废液 |
|---|---|---|---|
| 1 根基础管 | 119 B | 71.0% | — |
| **2 根基础管** | 238 B | **100%** | 238 B |
| **精确计量** | 90 B | **100%** | **90 B** |
| 赌博 | 10 B | 20% | 期望 50 B / 成功 |

  计量与洪水的差距是 **2.6×** → 计量在这里第一次真正值钱。

## 四、难度账（"更难"具体难在哪）

| # | 新增难度 | 玩家要做什么 |
|---|---|---|
| 1 | 富集矿石捷径删除 | 多一道磨粉工序，矿石吞吐 ×3 |
| 2 | 富集线多一道**强制解谐**，且唯一通路 | 造 42 个外壳的解谐器 + 一条硫酸管道 |
| 3 | 两道闸门都要求在**下界** | 整条 T2.4 精炼段搬到下界：供电、流体、跨维度运输。不去下界 = 吞吐 ÷1.5、总电 ×1.2 |
| 4 | 超能线入口改成粒子对撞 | 先跑通过充水晶 → 加速器 → 才能碰到粗超能硅岩 |
| 5 | 闸门② 单批 1 件、失败全损 | 必须先把成功率买到能承受的水平，再开机 |
| 6 | 阻尼液与回收线抢同一股废液 | 平衡「烧废液买成功率」和「电解回收氨/HF」 |
| 7 | 计量层（可选优化） | Jade 会显示 `Fluid fed this run: N mB`、GUI 显示 `Success chance: N%` → 玩家可以读表反推，把 F 调到 90 B 整数倍附近，省下 2.6× 流体 |

第 7 条是我特别想保留的：**机器自带遥测**，所以这不是"猜"，是一个可测量、可优化、有明确最优解的工程题。

## 五、要拍板的三件事

1. **闸门数量**：本方案是**两道**（富集线中段 + 超能线末端）。
   收敛到一道 = 只做闸门②，改动最小、但机器只出现一次；
   扩到三道 = 再在 `naquadria_oxide_dust` 或 `flawless_naquadria_gem` 上加一道（可用 `gallium_coolant`）。

2. **闸门①的阻尼液**：本方案用 `oritech:still_sulfuric_acid`（大宗、管道友好、在那个位置已经可得）。
   备选：`techreborn:mercury`（原版 `iridium_ingot` 配方用的就是它，但 TR 流体进不了管道，会直接卡死流程）。

3. **闸门②的批量**：本方案是 **1 件/次**（`naquadria_dust ×1`）→ 每件 90 B 废液 @100%。
   若觉得废液压力过大，可改成 2–4 件/次，每件成本线性摊薄，但失败一次报废整批。

## 六、还需要单独平衡的一件事（不在本次范围）

超能线现有收率是 **10 粗超能硅岩 → 1 超能硅岩粉**（4a 8→5、4b 5→3、4c 3→2、5/6/7/8 各 1:1）。
叠上 C 段的粒子对撞（2400 tick/个）后，**1 个超能硅岩粉 ≈ 24,000 tick 的加速器时间**。
这个比例会让闸门② 的 90 B 废液显得微不足道，也会让整条线慢到不合理。
建议在本次重写之外，单独做一轮 nqdria 收率平衡（把 4a/4b/4c 的损失从 8→5→3→2 收敛到 8→7→6→5 之类）。
