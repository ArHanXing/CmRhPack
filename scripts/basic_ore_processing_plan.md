# 基础矿物处理链路重设计计划

> 本文是规划稿，不是实现文件。本轮不修改配方、注册表、材质或任务。
>
> 数据依据：当前 `scripts/!recipedump.txt`、上一轮已经修改的 `.zs`、`scripts/grinder_parity.zs`，以及用户提供的机器槽位约束。
> 设计稿中的旧参数不具有实现权威性；最终以新脚本为准。

## 1. 目标与边界

### 1.1 本轮要重写的范围

基础矿物包括：

- 铁、铜、锡、金、铅、银、镍、铝土
- 铀、铱、铂、钨
- 方铅矿、闪锌矿、朱砂、黄铁矿
- 红宝石、蓝宝石、方钠石、橄榄石、钻石、绿宝石、青金石、下界石英等基础矿物/宝石
- 盐矿石、岩盐矿石
- 与上述矿物直接对应的 TR/OR/jsonreg 矿石、粗矿、碎块、宝石、粉末和冶炼产物

### 1.2 明确排除

以下线路不纳入基础矿物重写：

- 金红石 → 钛线路
- 普通硅岩、富集硅岩、超能硅岩线路
- 油砂 → 原油线路
- PBI、聚乙烯、环氧树脂等已经属于下游材料的线路
- 未来的集成矿石处理厂

基础线路可以向这些线路提供原料，但不重写它们内部的处理步骤。

### 1.3 设计目标

1. T1 到 T2.3 逐层提高处理能力、产率和副产物质量。
2. T2 以后统一以 TR 机器作为基础矿物的主处理设备。
3. 每种矿物最多设计 0~2 类有意义的副产物，不为了填槽位强行增加副产。
4. 粉末 `dust` 是**最终品**，不是中间态。
5. 允许复用已有 `oritech:xxx_gem` 作为中间浓缩物；必要时注册新的浓缩物、浆液、盐类中间物。
6. 不让旧 OR 五级倍增链和新链叠加。新链落地时必须清退旧路径。
7. 所有配方先按机器槽位审计，再写 ZenCode。
8. 对于 jsonreg 注册物品，在 material_tags.zs 内补充其 Tag。

## 2. 已观察到的现状

### 2.1 两套基础处理体系并存

当前 dump 中大致存在：

- TR `grinder`：约 157 条配方
- TR `industrial_grinder`：约 138 条配方
- OR `pulverizer`：约 99 条配方
- OR `grinder`/Fragmenting：约 80 条配方
- TR `extractor`：主要是染料、容器等通用提取，不是当前基础矿物主线

上一轮的 `grinder_parity.zs` 已经把小磨粉的能力缺口互通，但它不是最终矿物链；本计划落地时应把它纳入清退和重建顺序。

### 2.2 当前 OR 金属链的实际结构

以铁为例，当前已有的 OR 体系近似为：

```text
矿石
  -> 粉碎机：粗铁 x2
  -> OR 碎裂机：铁碎块 x1 + 小铁碎块 + 小镍碎块
  -> 干离心：铁石 x1 + 小镍粉
  -> 水离心：铁石 x2
  -> 硫酸酸洗：铁石 x3 + 矿物浆液
  -> OR 铸造炉：2 铁石 -> 3 铁锭
  -> TR 合金炉兼容配方：2 铁石 -> 4 铁锭
```

另一条 OR 地狱火路线是：

```text
粗铁
  -> 地狱火精炼厂：铁碎块 x2 + 岩浆
```

因此旧体系已经能形成极高的倍增。新体系不能在这个基础上再追加一套同等增产路线，否则会产生叠加倍率。

### 2.3 当前 TR 体系

TR 小磨粉机主要提供低成本、低副产的粗矿/粉末路线；TR 工业磨粉机提供：

- 水：主产物数量提升
- 汞：主产物与贵金属副产
- 过硫酸钠：主产物 + 金/镍/锌等副产

TR 工业磨粉机配方最多 4 个物品输出，但新设计建议通常只用：

- 1 个主产物
- 0~2 个副产物
- 第 4 个槽位只在确实需要时使用

### 2.4 盐系现状

当前已有：

```text
salt_ore      -> salt_dust x4
rock_salt_ore -> rock_salt_dust x4

salt_dust     -> chlorine + sodium
rock_salt_dust -> chlorine + potassium
```

化学定位已经很清楚：

- 盐矿视为 NaCl 来源
- 岩盐视为 KCl 来源
- 二者不能简单互换成同一种盐
- 当前没有必要为盐矿强行增加金属副产物

## 3. 新体系的阶段结构

## Tier 1：干法粗处理

### 解锁机器

- TR 磨粉机
- TR 提取机
- OR 基础离心机

### 设计目标

Tier 1 只解决“把矿变成可以继续处理的原料”，不解决完整提纯。

硬规则：

- TR 磨粉机 1 输出槽，全部配方严格 1 输出。
- OR 粉碎机的互通版本也只保留 1 输出。
- 不产生副产物。
- 不使用酸、过硫酸钠、地狱火、魔法催化剂。
- 不使用 `xxx_clump` 或 `xxx_gem` 作为最终产物。

### 建议的通用流程

```text
矿石 -> 粗矿 / 初级矿物粉 -> 可进入 Tier 1.5
```

主产物应统一到已有 TR/OR/jsonreg 材料标签，避免同一元素同时出现多个互不兼容的粉末。

对于不同类型矿物：

- 金属矿：矿石 → 粗矿或初级粉
- 宝石矿：矿石 → 宝石原矿或初级碎料
- 盐矿：矿石 → `salt_dust` / `rock_salt_dust`
- 铀矿：矿石 → 粗铀或铀矿粉，不在 T1 生成钚副产
- 铂族矿：矿石 → 粗铂/粗镍/粗铱，不在 T1 生成完整贵金属粉

### Tier 1 副产规则

Tier 1 不出副产。任何 `主产物 + 小撮粉 + 另一种金属` 的旧配方都不应继续挂在小磨粉机上。

## Tier 1.5：湿法处理与初级浓缩

### 解锁机器

- TR 化学反应釜
- OR 精炼厂
- TR 蒸馏塔
- OR 粉碎机/碎裂机作为较高处理能力设备
- OR 流体离心机

### 核心目标

把 T1 的粗矿转成“浓缩物”，但仍不直接产出最终 `dust`。

推荐的中间物优先复用：

- `oritech:xxx_clump`：碎块/粗精矿
- `oritech:xxx_gem`：湿法分离后的矿物浓缩物
- 新注册的 `xxx_slurry` / `xxx_solution`：只在确实需要区分溶解态时使用
- `xxx_tailings` / `xxx_waste`：需要进入回收或废物处理的尾矿

### OR 精炼厂的使用原则

OR 精炼厂的输入是 1 个流体 + 1 个物品，最多输出 3 个流体。

设计约束：

- 第一个流体输出必须是主产物。
- 第二、第三输出只用于真实的副液、尾液或回收液。
- 即使放弃后两个输出槽，配方也必须仍然可执行；不能把未输出的副液当作“隐形回收”。
- 精炼厂的增产来自溶解、选择性分配或浸出效率，不是无条件复制物质。

### OR 流体离心机

输入输出均为：

```text
1 个流体 + 1 个物品 -> 1 个流体 + 1 个物品
```

可用于：

- 粗浆液 → 浓缩液 + 尾渣
- 硫酸浸出液 → 浓缩液 + 矿物浆液
- 水洗/酸洗后的液相分离

`xxx_gem` 可以作为这一阶段的主要固体输出，但它应被定义为**浓缩中间物**，不是最终材料。

> **实现落地（2026-09-26 调整）**：Tier 1.5c 重结晶的试剂由硫酸改为**水**，
> Tier 2a 浓缩的试剂由硫酸改为**氢氧化钠溶液**。原因：这两步原本都用硫酸，而 T1.5c（3 粉）
> 与 T2a（5 粉）共用同一个输入「碎块」，试剂再相同会让 T2 完全支配 T1.5，gem 路线沦为空转。
> 拆开后硫酸专属 Tier 1.5a 酸浸；T1.5 = 低门槛低产（只需酸 + 水），
> T2 = 高门槛高产（氢氧化钠溶液需蒸馏塔出盐水 + 工业电解机）。

### Tier 1.5 的副产规则

每种矿物最多设计 0~1 种副产，且副产必须满足以下至少一项：

- 是该矿物共生矿物的合理残留
- 能在后续化学处理中回收
- 是酸浸、沉淀或溶剂回收产生的真实副液

## Tier 2：工业分离与副产物

### 解锁机器

- TR 工业磨粉机
- 所有 Tier 2 机器的 16 并行版本
- TR 大型化学反应釜
- 工业磨粉机的水、汞、过硫酸钠等流体工艺

### 核心目标

Tier 2 才开始把“矿物浓缩物”变成最终 `dust`。

```text
浓缩物 / 矿石
  -> 工业磨粉机 / 化学反应釜
  ->  dust + 0~2 类副产
```

### dust 定义

`dust` 是：

- 纯度足够高、可以直接进入冶炼/合金化的最终粉末
- 可以作为电炉、高炉、合金炉或后续特殊材料线的直接输入
- 不再作为下一阶段“浓缩”的中间物

后一类应改名为 `xxx_concentrate`、`xxx_clump`、`xxx_slurry` 或其他中间物，而不能继续用 `dust` 误导流程，实际模组环境都是 dust 粉作为高纯产物。

### 工业磨粉机的输出规则

每条配方最多：

- 1 个主产物
- 0~2 个副产物
- 最多 4 个物品输出

不允许使用小磨粉机的多输出配方，因为 TR 小磨粉机只有 1 个输出槽，执行会 NPE。

### 过硫酸钠路线

保留为 Tier 2 的工业氧化/浸出路线：

```text
硫化钠 + 压缩空气 -> 过硫酸钠
矿石 + 过硫酸钠 -> 主产物 + 有选择的金属副产
```

设计约束：

- 不是所有矿都必须有过硫酸钠版本。
- 优先用于铜、金、铱、锡、闪锌矿等已经有现成 TR 路线的矿物。
- 过硫酸钠路线的主要价值是改变副产结构，而不是无条件提高主产物数量。
- 不与 OR 酸洗、地狱火路线同时给同一种矿物叠加最大倍率。

## Tier 2.3：魔法催化与最大产值

### 解锁内容

- 灵魂注入催化剂
- 其他已经存在的魔法催化流体/中间物
- 与基础矿物处理连接的催化配方

### 设计原则

魔法催化不再创建一条全新矿物链，而是强化 Tier 2 的一条既有步骤：

- 提高主产物纯度或数量
- 提高副产物回收率
- 降低酸、溶剂、过硫酸钠等补充量
- 让尾液回收更完整

禁止：

- 同一矿物同时叠加酸洗最大倍率、地狱火最大倍率、过硫酸钠最大倍率和魔法最大倍率。
- 让催化剂既作为消耗品消失，又把完整催化剂价值算入产出。
- 把最终 dust 重新当成浓缩中间物无限循环。

## 4. 产率与平衡约束

### 4.1 统一基准

每种矿物需要先确定一个“普通冶炼基准”：

```text
1 个基础矿石 -> 1 个基础锭
```

所有高级路线的最终主产物都以这个基准计算倍率，不再只看某一个中间物的局部产出。

建议上限：

- T1：约 1~2 倍基础金属价值
- T1.5：约 2~3 倍，但要支付酸/水/溶剂与机器能耗
- T2：约 3~5 倍总材料价值，副产物是主要奖励
- T2.3：约 4~6 倍，作为基础矿物处理的当前上限

具体倍率必须以“主产物 + 可变现副产物 - 所有试剂成本”计算，不能只比较主产物数量。

### 4.2 不能重复计算的内容

- 如果一条路线已经从矿石中产出 `xxx_gem`，后续不能再次把同一矿石残余当作完整金属来源。
- 酸洗得到的 `xxx_gem ×3` 与矿物浆液副产必须共同计价，不能两边都按满价值计算后再叠加。
- 地狱火路线的 `xxx_clump ×2` 已经是强化路线，不能再给它完整的酸洗最高倍率而不增加额外试剂成本。
- TR 工业磨粉机的水/汞/过硫酸钠分支应视为互斥配方，而不是同时可用的免费加成。
- 工业磨粉机输出的每种副产都要纳入槽位和总价值预算。

## 5. 槽位硬约束

- TR 磨粉机：1 输出。只允许简单 1→1 配方；任何多输出配方执行会 NPE。
- TR 提取机：1→1。适合容器、单一提取物或单一纯化结果，不承担多副产矿石处理。
- OR 基础离心机：1 fluid + 1 item → 1 fluid + 1 item。
- OR 精炼厂：1 fluid + 1 item → 最多 3 fluid。第一个流体是主产物；后两个必须是真实副产或回收液。
- TR 蒸馏塔：4 输入、6 输出。空单元与流体单元必须按实际容器数量配平。
- TR 工业磨粉机：1 fluid + 1 item → 最多 4 item。推荐 1 主产 + 0~2 副产。
- TR 大型化学反应釜：6 输入、4 输出。只用于确实需要多组分反应的矿物化学步骤。

## 6. 实现顺序（未来落地时）

1. 建立基础矿物注册/标签清单，确认每个主产物和副产物 ID。
2. 清退旧基础矿物链：
   - OR `pulverizer/ore`、`pulverizer/raw`、OR `grinder/raw`、`rawsheol`、旧 clump/gem/锭转换
   - TR 小磨粉、工业磨粉机、兼容配方中与新链冲突的基础矿物配方
   - 只清退基础矿物；不动金红石、硅岩、油砂和 PBI/塑料特殊线
3. 实现 Tier 1：矿石 → 粗矿/初级粉，严格 1 输出。
4. 实现 Tier 1.5：粗矿/初级粉 → 浆液、碎块、低纯浓缩物；建立酸/水/尾液循环。
5. 实现 Tier 2：浓缩物/矿石 → 最终 dust + 0~2 副产；加入水、汞、过硫酸钠分支。
6. 实现 Tier 2.3：用灵魂注入催化剂强化既有步骤，不新增并行倍增链。
7. 删除或迁移上一轮 `grinder_parity.zs` 中与新基础矿物路线冲突的互通配方。
8. 用槽位审计器检查所有新增配方，再进行游戏内 `/reload` 和实际运行测试。

## 7. 本轮结论

这不是“给旧配方继续加几条高级版本”，而是一次完整替换：

```text
旧 OR 五级倍增链 + TR 基础/工业链
                ↓ 清退
新的 T1 → T1.5 → T2 → T2.3 基础矿物链
                ↓
T3 集成矿石处理厂（未来一步处理，暂未实现）
```

`xxx_gem` 可以作为浓缩物复用；`dust` 统一改为最终品；副产物只保留有矿物学或工艺依据的 0~2 类；特殊矿物线不进入本次基础体系。
